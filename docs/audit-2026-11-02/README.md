# Полный аудит CCEC — 2–3 ноября 2026

**Область: текущий репозиторий CreateCityExpansionCore со всеми вложенными проектами.** Версия подготовленного мода — 1.0.2.14, базовый коммит — ff4959ec8267291c36dc245357c27fba28cf8216, ветка — main. Соседний самостоятельный CreateServerPlatform в область не входит.

Аудит включает инвентаризацию доменов, review изменений логистики и сохранений, проверку документации, сборки и доступные локальные тесты. Это не доказательство отсутствия всех дефектов и не приёмка production или игрового клиента. Рабочее дерево с предыдущими изменениями логистики сохранено.

**Deployment hold:** последующий выпуск выявил source/schema divergence и был отменён с восстановлением сервера. [Проверенный incident receipt](../releases/2026-11-03-compatibility-incident.md). Этот аудит первоначальной ветки не описывает всю активную production Cargo-систему.

## Исправления и очистка

Логистика получила отмену на любом этапе с отдельным учётом коробок в пути, физическое восстановление посылки отправителем и команды OP. Возврат денег не создаёт бесплатный товар. Помощник последовательно выбирает Packager/Postbox и предлагает единственную соседнюю пару. WorldMap показывает читаемую схему остановок, направление, иконки и анимацию с учётом настроек; полученная геометрия рельсов отличается от схемы. Завершённая 3 ноября параллельная работа добавила графитовые панели, бирюзовый акцент, переходы слоёв/terrain, возраст данных и Ctrl+F. Её изменения включены в общий финальный build.

Устранены ошибки проверок содержимого посылки, отката приёмки, назначения поездов, восстановления отправочного Packager и выбора дорожного бюджета. Native SavedData checks дополнительно подтвердили защиту будущего формата и ошибок финансового codec без замены данных пустым реестром. Формат экономики — 13; совместимость сохранений и проверки перечислены в отчёте логистики.

В ходе общего аудита исправлен отдельный P1-дефект Railway: будущий неизвестный формат больше не загружается как пустой реестр. Защита стоит после native loader, который перехватывает ошибки deserializer; Railway и Economy сохраняют raw NBT даже при forced save. Добавлены регрессии настоящего DimensionDataStorage с завершённой async I/O. Исправлена утечка поблочного доступа при замене сундука на сундук через разрушение: committed block hook отзывает прежний grant, сохраняет обновления состояния и обходит перенос Sable. Regression сначала упала на прежнем поведении, затем прошла 2165 проверок территории, включая API/bytecode контракт. Игровое исполнение mixin отдельно не подтверждено. Существующие Social/Daily/Onboarding проверки подключены к корневому check. В backend исправлены четыре устаревших ожидания номера схемы 11→14 в трёх тестовых файлах; production migrations не менялись.

Все существующие README/STATE актуализированы. Для вложенной платформы добавлен единый STATE. Исправлены версия, ссылки, команды, лицензия, численность шахты и описание миграции геологии. Исторические документы сохранены, generated/runtime данные не удалялись. Проверка документации обнаруживает новые README/STATE, проверяет локальные ссылки и сверяет хеши с сохранённой квитанцией. Хеши Markdown нормализуют CRLF→LF и не зависят от Git autocrlf.

## Открытые проблемы и приоритеты

1. **Блокер native launcher.** В snapshot нет social_links, presence, presence_ipc и settings::launcher_memory, хотя lib.rs их регистрирует. Нельзя называть весь launcher собираемым по одному зелёному frontend. Нужно восстановить согласованный исходный код, затем Cargo/NSIS и GUI acceptance.
2. **Proxy/config snapshot платформы.** Caddy allowlist не включает часть новых news/registration/Mini App endpoints; env example отстаёт от config classes. Требуются отдельная сверка эксплуатационной конфигурации и проверка соответствующих маршрутов. Live proxy не читался.
3. **Физическая логистика и GUI.** Нужен Minecraft-прогон с частичной поставкой, отменой на каждом плече, заполненным инвентарём, restart/unload, двумя поездами, однонаправленной дорогой и реальными Vault/Postbox. OpenGL, сеть и анимации не подтверждаются headless геометрией.
4. **Действительно потерянный груз.** Отмена не создаёт удалённое изъятие или автоматическую компенсацию неучтённой коробки. Отдельный административный процесс должен доказать судьбу груза; иначе появляется двойное получение.
5. **Версионность остальных SavedData.** Railway/Geology/Economy имеют разные защитные контракты; часть Social/Profile/Community/Onboarding не отклоняет будущую версию, часть реестров не имеет общего version field. Требуется отдельное совместимое hardening с fixtures.
6. **Региональная диспетчеризация.** Упорядоченная цепочка хабов реализована; полное автоматическое планирование сети и резервирование поездов на всех плечах остаются развитием системы.
7. **CI и среда.** GitHub workflow собирает корневой мод. Platform suites, Linux-only infra и PostgreSQL не входят в этот workflow; текущие локальные результаты не подменяют их будущую CI-проверку.

Полные контекст, доказательства и дополнительные наблюдения находятся в трёх профильных отчётах. Review не устанавливает абсолютную безопасность кода по нулевому количеству taint findings. GitNexus graph/PDG дополнен чтением source, ресурсов, JUnit wiring и реальных test results; ограничения разрешения динамических вызовов сохраняются.

## Воспроизведение проверки документации

~~~powershell
node tools/audit-docs.mjs
~~~

После намеренного обновления документации просмотрите diff и пересоздайте квитанцию:

~~~powershell
node tools/audit-docs.mjs --write
node tools/audit-docs.mjs
~~~

Сохранённый baseCommit используется и после commit, поэтому проверка не теряет историю охвата. Дополнительные флаги --base и --date позволяют создать новый срез. Проверка не оценивает достоверность текста и не проверяет доступность внешних URL.

В этом аудите не выполнялись deployment, рестарт сервисов, публикация release, изменение секретов/прав или миграция внешних БД. Финальная публикация исходников в GitHub выполняется обычным commit/push по прямому поручению пользователя.
