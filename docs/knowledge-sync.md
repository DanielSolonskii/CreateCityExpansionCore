# Обновление базы знаний без сборки мода

На сервере статьи остаются в папке `CCEC - knowledge base` в рабочем каталоге игры.
Поддерживаются UTF-8 Markdown (`.md`) и PNG. Подпапки, ссылки между статьями,
относительные пути изображений, `title`, `icon`, `parent_item` и `default: visible`
сохраняют прежний формат. Например:

```markdown
---
title: Промышленная шахта
default: visible
parent_item: createcityexpansioncore:mine_controller
---
# Промышленная шахта
![Схема](mine.png)
```

После изменения файлов администратор с уровнем разрешений 2 выполняет
`/ccec knowledge reload`. Проверка и подготовка выполняются в фоне. Команда
сообщает об успешной публикации либо ошибке; ошибочная редакция не заменяет
предыдущую. Для первого использования новой системы нужно обновить мод и на
сервере, и у клиентов. Для последующих правок статей JAR менять не нужно.

## Загрузка у игроков

Синхронизация использует только игровую фазу соединения. Клиент начинает её
после появления в мире, приблизительно через 3 секунды игрового времени.
Сервер передаёт каталог размеров и SHA-256; клиент запрашивает только
отсутствующие или отличающиеся файлы. Совпадающие файлы из собственной папки
игрока также можно использовать без скачивания. Одинаковые изображения
передаются один раз, даже если имеют несколько имён.

Клиент проверяет все файлы, готовит новую локальную редакцию и переключается
на неё целиком. При обрыве уже полученные целые файлы сохраняются для следующего
входа. Незавершённый файл скачивается заново. Пока база не готова, попытка
открытия показывает сообщение; при ошибке показывается сообщение об ошибке.
На экран во время обычной игры уведомления не выводятся.

После завершения чтение статей, картинок, поиск и переходы работают локально,
без запросов к серверу. Права открытия статей продолжают приходить отдельно.
Команда reload запускает обновление также у уже подключённых игроков; открытая
база закрывается на время установки новой редакции.

## Одиночная игра

Хост одиночного мира не начинает сверку и передачу файлов. Ему доступны все
статьи из собственной папки и завершённых скачанных баз, включая статьи,
скрытые прогрессией на сервере. Скачанные базы показаны отдельными группами.
Команда reload в одиночной игре не запускает серверную синхронизацию.

## Нагрузка и хранение

Настройки создаются в `config/ccec-knowledge.properties`:

```properties
globalKiBPerSecond=256
playerKiBPerSecond=64
libraryId=<постоянный UUID, создаётся автоматически>
```

Лимиты применяются через reload; допустимо 16–4096 КиБ/с. Общий лимит делится
между игроками с чередованием очереди. Учитывается небольшой запас на заголовки
пакетов. Это лимит полезных данных системы, а не точный предел сетевого трафика
всего Minecraft/TCP. Файлы передаются частями до 8 КиБ; серверное чтение выполняет
пул из двух рабочих потоков. Каталог сканируется при запуске и reload, а не при
каждом входе игрока. Первая полная загрузка всё равно расходует серверный трафик.

`.ccec-knowledge-server-cache` хранит опубликованные файлы по хешу: это позволяет
продолжать отдавать прежние данные, пока автор редактирует исходники. Совпадающие
файлы переиспользуются; ненужные старые версии очищаются перед следующим reload.
На время обновления могут храниться текущая и следующая редакции.

Клиентский кэш находится в `.ccec-knowledge-cache`. Он разделён по адресу сервера
и UUID базы; собственная папка игрока никогда не изменяется. После установки
ненужные старые версии удаляются. Общий кэш поддерживается в пределах 256 МиБ
очисткой наиболее старых других баз; перед загрузкой освобождается запас места.
Поэтому очень старые базы могут перестать быть доступны офлайн.

Предел одной базы — 64 МиБ и 2048 файлов, одной статьи — 1 МиБ, одного файла —
8 МиБ, изображения — 4096×4096. Не следует менять `libraryId` при обычной правке
статей: это идентификатор базы, а не номер редакции. Размещение закрытых статей
в локальном кэше намеренно разрешено: их скрытие служит игровой прогрессии.

## Проверки разработки

`-I tools/knowledge-check.init.gradle checkKnowledgeSync` проверяет каталог,
дельты, PNG, целостность, повторный вход, прерывание обновления и лимиты.
Для серверных GameTest дополнительно используются
`-I tools/auger-gametest.init.gradle -I tools/knowledge-gametest.init.gradle runGameTestServer`.
