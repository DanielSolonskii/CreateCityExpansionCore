# Несовместимость source branch и сервера — 2026-11-03

**Статус: прежний сервер восстановлен; выпуск нового CCEC удерживается до совмещения с актуальной Cargo-базой.** Windows alpha-0.1.32 и macOS alpha-0.1.32-mac.1 не переключались.

## Что произошло

Текущая main после синхронизации содержала старую экономику формата 12; логистическая работа подняла её до 13 и подготовила CCEC 1.0.2.14. Однако установленный серверный JAR 1.0.2.13 уже использовал Economy 15 и новую Cargo-систему. Номер версии JAR не определял совместимость состояния.

Предрелизная проверка сверила хеши, состав файлов и startup, но не сравнила формат действующего мира и registry IDs кандидата. Это ошибка выполнения выпуска. Первый JAR 1.0.2.14 (SHA-256 236a61278b6d8b7e9fd6ae0f4fe8cdc04e6b09aab73b86fc17bc081b8e5a4dac) был установлен через guarded deployment. Native DimensionDataStorage перехватил отказ Economy codec 15→13 и создал пустой реестр; один лежащий предмет cargo_router также оказался неизвестным новой сборке.

Процесс достиг Done, поэтому readiness и успешный build не были достаточной проверкой сохранности данных. Публикация клиентских каналов не выполнялась.

## Доказанная причина расхождения исходников

Git reflog показывает синхронизацию main 2 ноября в 21:59:43 (Europe/Minsk), с 43e5e6d на ff4959e. Перед ней локальный код был сохранён в stash codex-presync-main-2026-11-02:

- stash commit: 5dcfa302c841b6957653c4057106c26a83cd6c4c;
- index snapshot: 0839bbb1fd43fbb3aca217478f37c5b5f28c73c1;
- в нём Economy FORMAT_VERSION=15, CargoCommerceBook и 44 Cargo Java-файла;
- сохранённая локальная работа содержит и прежнее удаление старой логистики/металлургических мультиблоков; её нельзя применять как простой поверхностный откат одного файла;
- восстановленный production JAR содержит Cargo и не содержит старых railway/blast/coke/steel классов, которые main вновь включала.

Stash не удалялся и не применялся поверх общего дерева. Новые изменения WorldMap и логистики сохранены в коммите 74ab360 и последующей защитной работе. Для дальнейшей реализации требуется изолированное совмещение актуальной Cargo-базы с ними.

## Защита и дальнейшее действие

До публикации каналов добавлена проверенная на настоящем DimensionDataStorage защита raw NBT: отказ codec удерживает исходные данные в cache, а get отклоняет доступ после native exception boundary. Forced save сохраняет raw-data. Railway — 16 проверок, cancellation suite — 60; полный build/check — 72 задачи. Финальная промежуточная сборка af6bf2fab26d07f05d3a60c635de31b6489270bdb15d039b88df744280dd41b2 не установлена на сервер и не опубликована клиентам: она корректно блокирует format 15, но ещё не реализует Cargo-базу.

Обязательные следующие шаги: восстановить актуальную source-базу без потери новых изменений, перенести требуемую отмену в работающую Cargo-систему, сверить registry IDs и SavedData contracts до stop/deploy, обновить аудит по итоговому дереву, затем повторить согласованный выпуск Windows/macOS и сервера.

Локальные логи, полные SavedData, содержимое миров, UUID игроков и инвентари в Git не добавлялись. Копии и recovery receipts остаются на сервере; этот документ содержит только операционные метаданные.
