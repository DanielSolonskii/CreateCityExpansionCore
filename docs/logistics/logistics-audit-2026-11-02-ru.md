## Отмена для игрока

В карточке доставки: **Отменить доставку → подтверждение**.

1. Новые запечатанные отправления больше не выпускаются.
2. Уже принятое оплачивается из существующего товарного резерва.
3. Деньги за неупакованный остаток возвращаются заказчику.
4. За физические коробки сохраняется резерв. Они продолжают обычный путь, включая однонаправленную сеть.
5. Настоящая приёмка оплачивает соответствующий товар. Физический возврат отправителем освобождает резерв заказчика.
6. После обработки последней коробки отмена закрывается; полное фактическое получение всего заказа означает выполненную доставку.

Коробку для возврата нужно действительно найти и взять в основную руку. В карточке отправителя есть **Вернуть коробку из руки → подтверждение**, также доступна команда `/freight recover`.
Обычный игрок должен иметь право строительства в городе отправителя. Возвращаются реальные предметы с сохранением компонентов, в основные 36 ячеек; переполнение сохраняет коробку без изменения. Печать обрабатывается один раз.
Коробка не появляется заново по записи реестра и не телепортируется с поезда. Автоматического поиска по выгруженным чанкам нет.

## Инструменты администратора

- `/freight inspect <UUID>` — состояние отмены, неразрешённый груз, выплаты и возврат.
- `/freight admin cancel <UUID>` — объяснение последствий и подготовка команды подтверждения.
- `/freight admin cancel <UUID> confirm` — отмена любой существующей доставки с теми же правилами сохранения физического груза и резерва.
- `/freight admin recover` — восстановить содержимое реально удерживаемой отменённой коробки в инвентарь администратора для ручной передачи владельцу.

Административные действия требуют OP уровня 2. UUID копируется подписанной кнопкой в карточке; команды предлагают только разрешённые записи. Консоль может отменять и проверять, но восстановление требует игрока с реальной коробкой.

## Подключение оборудования

**Новая точка → ПКМ по Packager или Postbox → проверка пары → сохранить**.
Автопоиск просматривает только загруженные block entities в пределах 16 блоков и выбирает пару только при единственном подходящем варианте. Используемые другим пунктом блоки и чужая городская территория исключаются. При нескольких вариантах кандидаты подсвечиваются; игрок указывает нужный блок следующим ПКМ. Подбор не регистрирует точку автоматически и не проверяет физический конвейер.

Shift + ПКМ пустой рукой открывает параметры, где можно изменить имя и направление. Выход в режим строительства прекращает перехват обычного ПКМ. Проверки сервера при сохранении сохраняются.

## Карта

Существующая WorldMap сохранена: территория, железная дорога, масштабирование и остальные слои работают через тот же движок. В первоначальном срезе выбранная доставка выделялась латунным цветом; в общем выпуске 1.0.2.14 её оформление согласовано с графитовой диспетчерской картой и бирюзовым акцентом; остальные связи приглушаются. Остановки имеют номера, роль и доступность, есть прогресс приёмки, стрелки и умеренная анимация. Настройка уменьшения движения учитывается.

Движущаяся пиктограмма показывает направление схемы, а не измеренные координаты каждой коробки. Реальные известные координаты поездов остаются отдельными маркерами. Сервер ограничивает объём геометрии рельсов, поэтому полученный фрагмент не объявляется полным маршрутом.

## Дополнительные предложения по итогам аудита

1. **Приоритет P1 — жизненный цикл потерянного груза.** Если физическая коробка уничтожена или потеряна, резерв сознательно не освобождается по одному тайм-ауту. Следующий этап — отдельное административное разрешение спора с журналом доказательств и явным выбором финансового исхода; нельзя одновременно восстанавливать предметы по записи и оставлять настоящую коробку действующей.
2. **Приоритет P2 — полнота геометрии.** Добавить серверный флаг полноты и отдельный запрос геометрии выбранной доставки. Текущий общий лимит может отсекать путь; интерфейс теперь сообщает это ограничение.
3. **Приоритет P2 — доступность.** Перевести строки списка на полноценные виджеты с клавиатурным фокусом и narration. Текущие карточки и кнопки требуют игровой проверки с клавиатурой и разными масштабами.
4. **Приоритет P2 — большие сети.** Измерить стоимость snapshot и обходов назначений на реальном сервере; затем кэшировать инфраструктурные наблюдения по revision и ограничить объём общих связей. Не замедлять физическую приёмку вслепую.
5. **Приоритет P2 — защита печати вне штатной приёмки.** Проверить все способы ручного открытия, перепаковки и уничтожения Create Package в живой сборке. Однократность финансового реестра не заменяет контроль полного физического жизненного цикла предмета.
