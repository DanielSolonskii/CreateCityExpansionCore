# Редактор UI в игре (F7)

Инструмент для правки интерфейса прямо в запущенной игре: позиции, размеры и
тексты виджетов. Только клиент, только для разрешённых игроков, ничего не
отправляется на сервер.

## Как открыть

1. Зайти в мир под ником из allowlist (по умолчанию `goddzerzh` и `drannch1k`).
2. Открыть любой экран интерфейса (пилон, логистику, рынок…).
3. Нажать **F7** (категория «Create City Expansion Core» в настройках управления).

Повторное нажатие F7 или **Esc** — выйти из редактора (сам экран при этом не
закрывается: первое Esc гасит редактор, второе закрывает экран).

## Управление

| Действие | Как |
| --- | --- |
| Выбрать и перетащить элемент | ЛКМ |
| Изменить размер | **Shift** + перетаскивание |
| Сдвиг на 1 px | Стрелки |
| Сдвиг на 10 px | **Shift** + стрелки |
| Изменить текст | Двойной клик или **Enter** |
| Сбросить выбранный элемент | **R** |
| Справка по управлению | **H** |
| Сохранить / Откатить / Сбросить / Экспорт | Кнопки нижней панели |

Наведение на элемент показывает карточку: имя/класс, координаты, размер и сдвиги.
Звёздочка в бейдже `UI-РЕДАКТОР*` — есть несохранённые правки. На экранах без
виджетов бейдж показывает вторую строку: сколько элементов layout доступно
(или что правки пока нет — такие экраны ещё не подключены).

> Правка **текста** работает только для виджетов (двойной клик / Enter). У
> элементов ручной отрисовки текст правится в фазе 3 — геометрия уже двигается.

## Файлы

| Файл | Что это |
| --- | --- |
| `config/createcityexpansioncore/ui-editor-allow.txt` | Список разрешённых ников/UUID. Создаётся сам, правится без пересборки |
| `config/createcityexpansioncore/ui-edit/<Экран>.json` | Правки экрана: дельты `dx,dy,dw,dh` + `text` |
| `config/createcityexpansioncore/ui-edit/export/<Экран>.txt` | Экспорт для переноса значений в код (дублируется в буфер обмена) |

Правки применяются при каждом открытии экрана, даже когда редактор выключен.
Пустой набор при сохранении удаляет файл — экран возвращается к ванильной
раскладке.

## Механика и почему так

- **Дельты, а не абсолютные координаты.** Экраны пересчитывают раскладку под
  разрешение и GUI scale; сдвиг от исходной позиции переживает любую перекладку.
- **Ключ виджета — `индекс:ИмяКласса`.** Если структура экрана изменилась, имя
  под индексом не совпадёт и правка молча не применится — лучше не применить,
  чем сдвинуть чужую кнопку.
- **В режиме редактора клики и клавиши перехватываются** — случайно не нажать
  чужую кнопку, не отправить товар и не закрыть экран.
- **Автосохранение при закрытии экрана** — наработанное не теряется; кнопка
  «Сохранить» пишет файл немедленно.
- **Битый JSON не перезаписывается молча** — сохранение блокируется, файл
  сохраняется для разбора.

## Доступ

Allowlist сравнивает ники без учёта регистра; строка может быть ником или UUID,
`#` — комментарий. Это удобство, а не защита: редактор меняет только экран
своего владельца, серверные данные недоступны в принципе, поэтому скрытие от
посторонних достаточно как политика.

## Проверки

- `gradlew checkUiEdit` — headless-проверка модели, JSON, файлов, экспорта,
  allowlist и хуков layout (входит в `gradlew check`, сейчас 95 проверок).
- RU/EN ключи (`ui_edit.*`) держатся в паритете общей проверкой
  `tools/check-lang-encoding.py`.

## Ручные экраны (фаза 2)

Многие экраны мода (профиль, соцсети, пилон, карта) не создают виджетов: они
считают геометрию в layout-классе и рисуют всё вручную. Для них правки идут
через хук на выходе аксессоров layout-класса (`UiEditLayout.apply`):

- **Реестр.** Каждый прямоугольник layout регистрируется под именем элемента
  (`close`, `tab[0]`, `body`…) — оверлей обводит их и ловит клики там, где нет
  ни одного виджета. Виджеты приоритетнее: клик по виджету выбирает виджет.
- **Координаты.** Дельты хранятся в логических единицах layout (переживают
  GUI scale), обводка и перетаскивание — в экранных; конвертация в
  `UiEditLayout.toScreen/toLayout`.
- **Пересборка.** После отпускания мыши/стрелки/R экран пересобирается
  (`resize` → `Init.Pre/Post` ровно один раз) — layout-класс пересчитывает
  геометрию уже с новой дельтой, выбор элемента сохраняется.
- **Один файл.** Элементы лежат в том же JSON узлом `"elements"`; сессия и
  хук работают с одним объектом, поэтому «Откатить» перечитывает файл с диска
  и для элементов тоже (этим же приёмом применяется правка JSON руками).
- **Ключ экрана.** Хук не передаёт имя экрана: `UiEditEvents` объявляет
  текущий экран в `Init.Pre` (`UiEditLayout.setActiveScreen`), и элементы
  пишутся под `className` того же объекта, что читает сессия. Так
  структурно исключён баг рассинхрон ключа (хук писал `PlayerProfile`,
  сессия читала `PlayerProfileScreen` — обводок не было, правка молчала).
  Вне игры активного экрана нет — хук работает чистой проходной функцией.

**Подключено:** `PlayerProfileLayout` (все стабильные прямоугольники, кроме
scroll-зависимых `searchRow`/`scrollThumb` и статического `workspaceEntry`).

**Ещё не подключены** (бейдж показывает «правка в фазе 2»): пилон — сам
открывается как `CityPylonWorkspace` (ручной экран: рамка, сайдбар, навигация
рисуются без единого виджета, а страницы рендерятся внутри в масштабе
`origin+scale`), карта мира (`WorldMapScreen` считает геометрию инлайн, без
layout-класса), железные дороги/проекты. Подключение каждого — это обёртка
аксессоров того же вида.

## Ограничения

- Редактируется геометрия элементов ручной отрисовки; их **тексты** правятся в
  фазе 3 (нужен перехват `drawString`).
- Редактор работает в игре (нужен игрок в мире), не в главном меню.
- Правки, сделанные после `init()` экрана (виджеты, добавленные по событию
  сервера), применяются при следующем открытии.
- Правка JSON-файла руками во время игры подхватывается кнопкой «Откатить»
  (она перечитывает файл с диска).
