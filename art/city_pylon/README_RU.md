# City Pylon — модель для Blockbench

**Сверка состояния: 2026-11-04.** [Актуальный аудит CCEC/Cargo](../../docs/audit-2026-11-04/README.md) описывает интеграцию 1.0.2.15. Ранее датированные результаты проверок ниже сохраняют свою дату; новый игровой/production прогон ими не подтверждается.

Актуализировано **02.11.2026** по ресурсам и Java-коду. Модель подключена к моду:
есть `CityPylonBlockEntity`, `CityPylonRenderer` и четыре направления блока.
Общий статус: [CURRENT_STATE.md](../../CURRENT_STATE.md),
[аудит](../../docs/audit-2026-11-02/README.md).

Готовый редактируемый проект промышленного городского терминала: 90 кубов,
17 групп, 8 независимо управляемых частей. Габариты в исходной позе:
X/Z от 1 до 15, Y от 0 до 15.9. Лицевая сторона — north, то есть −Z.
Единица координат равна 1/16 блока. Сталь, латунные стойки и рамка,
медные кабельные каналы, три физические лампы и защищённый верхний индикатор.
Стекло экрана имеет размер 5.95 × 3.05 единицы; надписей и логотипов нет.

## Файлы

Текстуры обновлены по визуальным ориентирам из установленного Create 6.0.10:
`brass_block`, `railway_casing`, `industrial_iron_block`, `copper_casing`.
Использована их палитра; пиксельные узоры нарисованы заново. Добавлены тёплые
латунные кромки, ступенчатые блики и потёртости, крупные пятна литого металла,
рамки сервисных панелей с крепежом и отдельные блики на линзах.
UV сервисных панелей и линз скорректированы, оба атласа остаются 64×64.
Совпадающие передние плоскости зубьев шестерни разнесены максимум на 0.03
единицы модели для устранения мерцания текстуры. Иерархия и pivot сохранены.

- `city_pylon.bbmodel` — Generic Model для Blockbench 5.x, с встроенной текстурой,
  иерархией, pivot и тремя механическими reference-анимациями.
- `city_pylon.png` — основной RGBA-атлас 64×64, включая тёмные выключенные линзы.
- `city_pylon_emissive.png` — RGBA emissive-атлас: цвет светящихся участков,
  прозрачность вне них. Сталь, медь и латунь полностью прозрачны.
- `preview_front.png`, `preview_isometric.png` — рендеры исходной геометрии
  с примером спокойного активного состояния. Это не скриншоты игры.
- `preview_back.png`, `preview_off.png` — задняя сторона и выключенное состояние.
- `integration_manifest.json` — группы, координаты pivot, пути runtime-частей.
- `runtime/assets/createcityexpansioncore/` — Java JSON-части и обе текстуры
  в структуре ресурсов мода. UV пересчитаны из 64×64 в Java-диапазон 0–16.
- `validation.json` — результаты автоматических проверок.

Открытие: Blockbench → Файл → Открытие модели → `city_pylon.bbmodel`.
Текстура встроена в проект; PNG рядом предназначен для внешнего редактирования
и переноса в ресурсы. Не конвертируйте основной проект в Java Block/Item:
исходником для анимации остаётся Generic Model.

## Художественные reference-состояния

Таблица ниже сохраняет задуманный художественный контракт. WARNING, DATA UPDATE
и LEVEL UP не являются реализованными серверными событиями визуализации.
Текущее поведение описано в следующем разделе.

| Состояние | Поведение |
|---|---|
| OFF | Тёмные линзы и стекло, механика остановлена, emissive выключен |
| IDLE | Кольцо 6°/с; шестерня −12°/с; зелёная лампа постоянно; amber-вспышка 0.3 с каждые 4 с; экран едва меняет яркость |
| OPEN | За 0.4 с экран ярче, amber загорается; кольцо плавно ускоряется до 16°/с; зелёная и amber включаются последовательно; возврат после закрытия |
| DATA UPDATE | Amber мягко вспыхивает на 0.35 с |
| WARNING | Красная лампа: 0.7 с ON / 0.7 с OFF; без быстрого стробирования |
| LEVEL UP | 1.6 с: зелёная лампа → экран → верхний индикатор; мягкий пик индикатора; selector поворачивается на −22.5° и возвращается |

Reference-клипы в Blockbench: `idle_mechanical_reference` (60 с, loop),
`open_mechanical_reference` (1.5 с), `level_up_mechanical_reference` (1.6 с).
Они описывают механические движения. Цвет и emissive задаются renderer, а не
Blockbench-треками. OPEN-клип — образец движения; сами reference-клипы
не исполняются в Minecraft.

## Подключение к NeoForge 1.21.1 / Create 6.0.10

Действующая интеграция находится в следующих файлах:

- [CityPylonBlock.java](../../src/main/java/com/example/examplemod/block/CityPylonBlock.java)
  наследует `BaseEntityBlock`, создаёт BlockEntity, использует `RenderShape.MODEL`
  и `HORIZONTAL_FACING`.
- [CityPylonBlockEntity.java](../../src/main/java/com/example/examplemod/block/CityPylonBlockEntity.java)
  хранит и синхронизирует `Active`; фазы механики остаются клиентскими transient-полями.
- [CityPylonModels.java](../../src/main/java/com/example/examplemod/client/render/CityPylonModels.java)
  регистрирует 13 дополнительных моделей, включая emissive-варианты восьми групп.
- [CityPylonRenderer.java](../../src/main/java/com/example/examplemod/client/render/CityPylonRenderer.java)
  рисует подвижные части и индикаторы; регистрация находится в
  [CreateCityExpansionCoreClient.java](../../src/main/java/com/example/examplemod/CreateCityExpansionCoreClient.java).
- [blockstate](../../src/main/resources/assets/createcityexpansioncore/blockstates/city_pylon.json)
  содержит `static_body` для четырёх направлений; [item model](../../src/main/resources/assets/createcityexpansioncore/models/item/city_pylon.json)
  использует `inventory` со всеми частями.

Зелёная лампа и верхний индикатор следуют `Active`; amber мигает декоративно
и горит при открытом окне этого пилона. Красная лампа выключена: отдельный
warning-флаг не реализован. Экран имеет тёмную основу и emissive при `Active`.
Кольцо/шестерня вращаются, селектор реагирует на открытое окно. Скорости и фазовые
переходы нужно оценивать в клиенте: наличие констант в renderer не подтверждает
точные визуальные тайминги. Дальность отсечения renderer — 64 блока.

Контракт ресурсов при дальнейших изменениях:

1. Генератор пишет в `art/city_pylon/runtime/assets`, а действующие ресурсы лежат
   в `src/main/resources/assets`. После согласованного изменения перенести и
   проверить нужные файлы; генератор сам не обновляет рабочую интеграцию.
2. Сохранять регистрацию BlockEntity/renderer и дополнительных моделей.
3. Направить blockstate на `createcityexpansioncore:block/city_pylon/static_body`.
   Оставить обычный model render shape, чтобы базовый корпус рисовался миром.
   Renderer рисует только восемь отдельных частей. Не рисовать static_body
   ещё раз через BER.
4. Для предмета использовать parent
   `createcityexpansioncore:block/city_pylon/inventory`. Только inventory-модель
   содержит все части в исходной позе: это намеренный неподвижный item fallback.
5. Зарегистрировать загрузку каждой дополнительной модели на клиенте; JSON,
   не связанный с blockstate, не следует считать автоматически загруженным.
   При использовании Create PartialModel перечислить восемь ресурсов явно.
6. Применять к каждой подвижной части transform вокруг pivot из manifest:
   `translate(pivot / 16) → rotate → translate(-pivot / 16)`.
   Координаты частичных моделей абсолютные, в системе блока, не локальные.
   Встроенные повороты кубов у шестерни и фасок кольца уже входят в JSON.
7. Рендерить светящиеся группы с основным либо emissive-материалом в зависимости
   от состояния. Для emissive задавать full-bright lightmap только этим частям.
   Имена соответствующих моделей имеют суффикс `_emissive`. Не выводить обе
   непрозрачные поверхности одновременно: они совпадают и дадут z-fighting.
   Для плавной яркости модулировать цвет/свет в одном проходе материала.
   Сам по себе PNG с таким именем не включает свечение в vanilla/NeoForge.
8. `Active` приходит с сервера. Для будущих WARNING, DATA UPDATE и LEVEL UP
   потребуется реальная привязка к событиям; декоративный таймер её не заменяет.
9. Сохранять одинаковый поворот static-body blockstate и BER вокруг центра
   блока (8, 0, 8). Исходная ориентация модели — NORTH (−Z).

Экран обращён наружу на Z=2.39. Будущие символы можно рисовать отдельным quad
чуть перед стеклом (например Z=2.38), в пределах X=4.25…10.2, Y=8.4…11.45.
Надписи в основном атласе отсутствуют.

Для collision/selection рекомендуется объединение `box(1,0,1,15,2.85,15)`,
`box(2,2.85,3,14,13,14)` и `box(4.5,13,5.5,11.5,15.9,12.5)`.
Передняя панель может быть добавлена как `box(2.8,6.7,1.9,13.2,12.4,5.2)`.
Первые три объёма уже применены в `CityPylonBlock.SHAPE`; отдельный передний
объём остаётся предложением. Текущий Java shape возвращается одинаковым для
всех facing — совпадение collision/selection с повернутой моделью проверять
в клиенте отдельно.

## Проверка и воспроизведение

При первоначальной подготовке проект был открыт в веб-версии Blockbench: 90 элементов, иерархия из
17 групп, 64×64 текстура и три клипа в режиме «Анимация».
Автоматически проверены уникальность UUID, положительные размеры кубов,
границы UV, отсутствие повторов между static/dynamic, геометрия внутри
блока и габариты кольца при вращении с шагом 5°. Превью визуально проверены.
В аудите 02.11 повторно проверены 90 кубов, уникальные UUID, размеры, UV,
PNG-заголовки 64×64 и 15 действующих JSON-моделей. Все 17 файлов экспортного
`runtime/assets` побайтово совпали с соответствующими ресурсами мода.
Генератор и Minecraft-клиент не запускались. Сохранённый `validation.json`
с фразой об отсутствующем renderer описывает первоначальный этап, а не нынешний
Java-код. [Подробности](../../docs/audit-2026-11-02/TOOLS_ART_AUDIT_RU.md).

Генератор: `tools/build_city_pylon.py` в корне репозитория, Python 3 + Pillow
и numpy. Он создаёт модель, атласы, части и программные превью. После ручного
редактирования в Blockbench не запускайте генератор поверх изменённого проекта
без сохранения копии: генератор воспроизводит исходную авторскую версию.

```powershell
python tools/build_city_pylon.py
```

Структура bbmodel 5.0 сверена с
[официальной документацией Blockbench](https://www.blockbench.net/wiki/docs/bbmodel/).
